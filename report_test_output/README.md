# Report Generation Test Output

Generated by running the three report API endpoints against the running eXueed API.

## Generated Reports

| File | Endpoint | Description |
|------|----------|-------------|
| `patient-match-report.pdf` | `POST /api/report/patient-match` | Patient-trial matching results with match scores and rationale |
| `treatment-comparison-report.pdf` | `POST /api/report/treatment-comparison` | Side-by-side treatment comparison (efficacy, safety, dosing, outcomes) |
| `query-report.pdf` | `POST /api/report/query` | Evidence-based query answer with sources |

All three are valid PDF 1.4 documents generated via ReportLab.

## Query Report Formats

The `/api/report/query` endpoint accepts a `format` field in the request body:

| Format | Description |
|--------|-------------|
| `standard` (default) | Question + Answer + Details + Sources table |
| `patient_handout` | Patient-friendly language with key takeaways |
| `clinic_note` | Clinical question + Recommendation + Evidence summary + Next steps |

## Running the Tests

Unit tests for the report service are in `tests/test_report_generation.py`. They validate PDF generation without requiring a running server:

```bash
pytest tests/test_report_generation.py -v
```

The API integration test (marked `@pytest.mark.skip`) requires the server running at `localhost:8000`.

```json
{
  "patient_summary": "65-year-old male with NSCLC",
  "total_matches": 1,
  "matches": [
    {
      "title": "Study Title",
      "author": "Author",
      "year": 2022,
      "match_score": 0.9,
      "match_strength": "strong",
      "match_rationale": "Rationale text",

```
